## Per gap

**G34 / G38: adaptive chunk (fixed).**
- `LiveRun::with_target_wall(Some(s))` sizes each chunk from the previous chunk's measured `advance` time per sim
  second, so that a chunk takes about `s` of wall time.
  - The bounds are [chunk/1024, chunk], and the caller's chunk stays the maximum.
  - Growth is at most 2x per chunk.
  - The first chunk is full size, because nothing has been measured yet.
- Boundaries are `pos × (chunk/1024)`, where `pos` is an integer count, so they are never a running sum.
  - A run that never shrinks has boundaries bitwise equal to `k × chunk`.
  - The 30000-chunk exactness test is unchanged and passes.
- Python: `LiveRun(..., target=None)` and `Simulation.live(..., target=None)`.
- `LiveSession(doc, ..., target=TARGET_WALL)` (0.05 s) turns it on for the app.
- G38 is the same fix: New, Open, example loads and close wait for at most one chunk, now about 50 ms after the first.
- Tests:
  - `tests/live.rs::adaptive_chunks_follow_the_wall_time_target_within_bounds`: floor, maximum, exact boundaries, a
    change on a boundary, a bad target refused.
  - `test_live.py::test_adaptive_chunks_shrink_to_meet_the_wall_time_target`.

**G35: explicit live params (fixed).**
- `[sim.electrical] live = [...]` overrides the derived rule, and `[]` means none.
  - `electrical.check` validates it (a list of param keys, DEF-SIM).
  - `sim._live` filters the keys. A part with no live key declares no devices.
- 29 packages are curated:
  - `[]`: capacitors (ceramic, electrolytic, film, tantalum), crystals and the ceramic resonator, ultrasonic piezo,
    OPAMP_MACRO, SCR, IGBT, IND_DCR, SOLENOID, SPEAKER, MIC_ELECTRET;
  - `["state"]`: switches and push buttons;
  - the stimulus only: HALL_LINEAR, LM35, POSITION_SENSOR, PRESSURE_BRIDGE, DC_MOTOR;
  - `["R"]`: R_TOL;
  - `["R", "pos"]`: POT and RHEOSTAT.
- Tests cover the curated parts, a catalog-wide check that every listed key is one the rule can alter, a bad key as
  a DEF-SIM error, and `[]` refusing a change.
- `docs/library.md` does not change: the generator does not show the key.

**G39: apply final values (fixed).**
- "Apply live values" sits in the results banner beside Replay, and in Simulation > Apply live values.
  - It writes the last applied value per (part, param) from the session's change log into the document, as one
    `History` step, using `repr(float)` (round-trips exactly; choice params keep their text).
  - It is enabled only after a live run with changes, while that result is shown.
  - The result is then stale, because the run simulated the starting values.
- Test: `test_live_ui.py::test_apply_live_values_writes_the_final_values_as_one_undoable_edit` (undo and redo).

**G40: tstop defaults (fixed).**
- `sim.pin_tstop_defaults` rewrites every V/I time function whose value falls back to ngspice's tstop default
  (missing or 0) to the batch stop time's value:
  - PULSE `pw`/`per` = tstop;
  - SIN `freq` = 1/tstop;
  - SFFM `fc`/`fs` = 1/tstop.
  - Missing earlier slots get ngspice's own tstop-free defaults (td 0, tr/tf = tstep).
- It applies to the live deck and to `LiveSession.replay`. That replay is a batch run of another length, so it
  needed the same fix.
- A source it cannot check (no parentheses, split over `+` lines, or AM missing MF/FC) is refused with a clear
  "Live run refused" message, but only when the live duration differs from the stop time.
- A `{expression}` slot counts as given. If it evaluates to 0, ngspice still falls back to its default. This
  limitation is documented, not handled.
- Tests:
  - the rewrite unit test;
  - end to end: a package PULSE with no period repeats every 2 ms (the stop time) in an indefinite run. With the pin
    disabled this test fails.

**G41: layout (fixed).**

  clipped "Indefinite" by about 3 px.
- Below 1240 px the menu button shows its logo only; its menu and tooltip stay.
- The field-label and dark-toggle threshold moved from 1150 to 1170. The old thresholds squeezed the menu button and
  made the icon buttons overlap between 1150 and 1235 px.
- Measured offscreen, every width from 1024 to 2199 px: no overlap, nothing squeezed below its size hint, and the
  field shows "Indefinite" and "Stop time" whole.
- Test: `test_live_ui.py::test_the_live_for_field_is_never_clipped_and_the_top_bar_fits`, at 10 widths, using the
  running font's metrics.
- The "Live for" caption is still hidden below 1520 px (unchanged; the field keeps its tooltip).

**G42: run history (fixed).**
- `sim.Overview` is fed every chunk on the worker thread and holds at most 2000 buckets.
  - Each bucket keeps every series' min and max, with their times.
  - When the buckets overflow, they merge pairwise.
- When the session ends, the coarse record from before the retained window is put in front of `result.series`. It
  uses two points per bucket, on one shared time base.
- `_live_done` adopts the session's series, so after Stop the plot, cursor and stats cover the whole run. The run's
  min and max are exact.
- Tests:
  - an `Overview` unit test: 1e6 points, bounded, extremes exact, ordered;
  - end to end: a lux spike long out of the window keeps its exact value;
  - the memory test now also checks the bucket bound;
  - the 9.7 tests that asserted "only the window is kept" now assert the window is in full and everything before it
    is coarse.
