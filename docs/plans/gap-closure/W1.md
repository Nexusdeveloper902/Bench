# W1: AC small-signal analysis (G17) and the AC source (G13)

Base: 35e0a24 on `feat/multi-terminal-transistors`. Out of scope, as planned: noise, pole-zero and `.dc` sweeps.

## Probe: libngspice complex vectors (ngspice 47, `/usr/lib/libngspice.so`)

These were run through the same `ngSpice_Init` / `ngSpice_Circ` / `run` sequence as `benchcore/src/ngspice.rs`. The scripts were scratch ctypes probes on top of `probes/ng_probe.py`.

- **Plot and vector layout:**
  - `.ac` makes a plot named `ac1`, `ac2`, ... and `ngSpice_CurPlot` returns it.
  - Every vector in it, `frequency` included, has `v_realdata == NULL` and `v_compdata` set. `v_compdata` is an `ngcomplex_t {double re, im}` array of length `v_length`.
  - `frequency` is complex with a zero imaginary part.
  - `v_type` is 2 for frequency, 3 for voltage and 4 for current. `v_flags` is `0x82` (complex).
  - The existing `read_vec_from` returns None for all of these, which is why a transient read of an AC plot gave empty series.
- **Name lookup:** `ac1.v(out)`, `ac1.i(v1)` and `ac1.v1#branch` all resolve through `ngGet_Vec_Info`.
- **Device `@` vectors in AC:**
  - `@d1[id]`, `@q1[ic]` and `@i1[c]` have the full length but hold the **operating-point value repeated at every frequency** (real, constant). They are not small-signal currents.
  - `@r1[i]`, `@c1[i]` and `@l1[i]` have length 0.
  - The engine therefore refuses `@` observables in AC runs, and the app leaves those currents out with a note. Source branch currents (`i(vsrc)`) are true small-signal values.
- **Stimulus:** the source phase is in degrees: `AC 2 90` gives `0+2j`, and `AC 1 45` gives `0.707+0.707j`. `DC x AC m p` and `SIN(...) AC m p` are both accepted.
- **Silent failure:** `.ac dec 10 0 1k` (fstart 0) makes no AC plot, logs nothing and returns rc 0, leaving the current plot at `const`. The engine refuses `fstart <= 0` up front and treats "current plot is not `ac*`" as a SolverError.
- **ngspice bug:** `.ac lin 2 a b` returns **one point** (fstart) for every a and b. `lin 1` and `lin 3` and up are exact. The engine refuses `lin 2` and checks that a lin sweep returns exactly n points.
- **Sweep end points:** a `dec` or `oct` grid ends at the last whole step at or below fstop. For example, `oct 3 1 10` ends at 8 Hz, and `dec` includes fstop.
- **Operating point:** there is no `uic`, so ngspice solves the operating point first. A capacitor-only node produces "singular matrix" warnings. The validator already refuses that case: its topology treats capacitors as connections only under `.tran ... uic`, so an AC deck gets NO-DC-PATH.
- **Poisoned engine:** an aborted (poisoned) engine is reloaded by the existing `after_call` path. An AC run after a reload succeeds (`ac06`).

## What was built

**Engine:**
- `ngspice.rs`: `read_cvec_qualified` reads `v_compdata`.
- `kernel.rs`:
  - `ac_sweep` checks the deck's single `.ac dec|oct|lin n fstart fstop` card. The checks are: exactly one analysis card; a whole number of points of at least 1; `0 < fstart < fstop`; no `lin 2`; and at most 1e6 points.
  - `run_ac` follows the transient path's discipline: op lock, live refusal, validator gates, `with_reason`, `scan_loud_failure` mapped to Convergence or Solver errors, and the reload-on-abort path. It returns the frequency grid and `(re, im)` series.
  - `run_simulation` now refuses an `.ac` deck. Before, it returned success with empty series.
- `lib.rs`: the `benchcore.run_ac(deck, observables)` binding.
- Python: `Simulation.ac(sweep, points, fstart, fstop)`, plus a `frequency` property. `observable()` returns `(re, im)` pairs.
- Live runs need no engine change: `LiveRun` already refuses a deck without `.tran`.

**Packages (G13):**
- `V` and `I` gain `ac` (AC magnitude, V or A, default 0) and `acphase` (AC phase in degrees, default 0). Each also gets a new `[sim.electrical] ac = "AC {ac} {acphase}"` key.
- `electrical.py`:
  - accepts the `ac` key only on V and I devices, with an `AC ` prefix and placeholders limited to always-applicable params;
  - appends it **only in AC decks** (`build_netlist(..., ac=True)`), so transient decks and the golden netlists are byte-identical;
  - leaves live-device detection (`_VALUE_LINE`) untouched.
- Package versions are not bumped, because a parameter added with a behaviour-preserving default loads old files with that default.
- `docs/library.md` regenerated with no change.

**App:**
- `model.py`:
  - `Document.analysis` is `"transient"` or `"ac"`. `Document.ac` holds `{sweep, points, fstart, fstop}` as typed.
  - `ac_sweep()` validates it and applies the same `MAX_POINTS` / `MAX_SAMPLES` limits as transient runs.
  - `config()` returns `{"ac": (...)}` for AC.
  - Persistence: `simulation.analysis` is written as is. `simulation.ac` is written only when it differs from the defaults.
  - Old files without `analysis` load as transient. An unknown analysis, sweep or AC key is a `bad simulation file` error.
- `sim.py`:
  - AC runs go through `_run_ac`. Series are `[(f, complex)]` and across-part signals are complex differences.
  - `RunResult.analysis` is set to "ac".
  - Device `@` currents are left out with a message note, and an all-zero result says to give a source an AC magnitude.
  - `LiveSession` and `replay_document` block an AC document with "Live runs are transient only: switch the analysis to Transient to run live."
- `results.py`: the Bode view.
  - Magnitude in dB (solid, left axis) and phase in degrees (unwrapped, dashed, right `twinx` axis) on a log frequency axis with an engineering Hz formatter.
  - Cursor: the slider moves on a log scale, a click sets it, and the readout shows `f = …  V(x) = -3.01 dB  ∠ -45.0°`, interpolated on the log axis as drawn.
  - Stats show the peak dB and its frequency. Play is disabled for AC.
  - The twin axis was chosen over stacked axes because the dock is 248 px tall.
- `window.py`:
  - The analysis chip is now a Transient / AC picker that stays visible at every width.
  - The AC sweep fields (sweep, points, from, to) replace stop time and step in AC.
  - Only the shown analysis' field errors block Run. The stale key includes the analysis and the sweep.
  - Live is disabled in AC, with that message as its tooltip and status.
  - The LED glow and part current are off for AC results.
- `inspector.py`: the "Simulation" section takes `(label, value)` pairs, so it shows the sweep for AC. This is not a live part.

## Known limits

- Only `V` and `I` carry an AC stimulus. `ISRC_WAVE`, `VSRC_EXP_SFFM`, the PWL sources and batteries are 0 in AC, so they act as shorts or opens there. Adding the stimulus to another package means adding the two params and the `ac` key.
- AC device currents (R, C, L, diode, BJT, ...) are not shown: ngspice gives no small-signal value for them (see the probe). Measure through a 0 V source, or use the across-part voltage.
- The magnitude floor is 1e-30 (-600 dB) so that exact zeros plot.
