# W5: vendor-model path (G10, G19)

## G10: `compat = "ps"`

**Mechanism.** `[sim.electrical] compat = "ps"` (needs `defs`, no `body`). `electrical.build_netlist` then emits, for
each such file, `* bench-def <label> <sha8>` and `.include "<abs path>"` instead of the inlined lines, and one
`* bench-compat: ps` comment per deck. `benchcore/src/ngspice.rs::do_circ` (the one choke point for batch, AC and
live) looks for that comment and, if present, sends `set ngbehavior=ps` right after the existing `unset ngbehavior`.
The marker is an in-band deck comment, so no API, wheel interface or live-session change was needed. A deck without a
marker takes the same calls as before; the golden netlist tests pass unchanged.

**Probes, ngspice 47.**
- `set ngbehavior=ps` through `ngSpice_Command` before `ngSpice_Circ` works (as HANDOFF said). Order matters: Bench's
  `unset` must come first, then `set`.
- No leak: after a ps run, a marker-free deck is back to plain (same file, no marker: `LIMIT()` gives 0.0, with the
  marker 1.9998 for a 3 V input clamped at 2 V). Tested at engine level (`benchcore/tests/python/test_api.py`) and app level.
- Without ps, an included `IF()` aborts ("no such function 'if'"), but an included `LIMIT()` is silently 0: a wrong
  "success". That is the real reason the opt-in must be explicit.
- **Per-file scope does NOT hold.** The manual (and HANDOFF) say `ps` applies to included files only. Probed: a
  `B1 V=limit(...)` in the MAIN deck is translated too (2.0 under ps, 0.0 plain). Twelve native B-source forms (`log`,
  `ln`, `log10`, `**`, `^`, ternary, `pwr`, `sgn`, `floor/ceil`, `min/max`, `abs/sqrt/exp/atan`, `u/uramp`) plus `.param`
  and a diode gave identical values in both modes (`test_ps_mode_does_not_change_native_main_deck_expressions`). So an
  opted-in deck is safe for Bench-authored lines in everything probed, but the guarantee is empirical, not structural.
- `.spiceinit` `psa` is still overridden by the pin when there is no marker (existing test unchanged).

**Validator.** It does not read `.include` files, so it cannot falsely reject them; an instance of such a subckt gets a
`warn` `OPAQUE-X` ("its .subckt is not in the deck ... body is not analysed"). It also cannot check them: PSpice text
inlined into a probe deck would be refused (`limit()`, `IF()`, `VSWITCH` are `UNSUPPORTED`), so for `compat = "ps"`
packages `validate_bodies` is skipped, the status is `limited` and the package's limitations get that sentence
automatically. What is still checked at load: header allowlist (no `.control`, which `.include` would otherwise run),
balanced `.subckt`/`.ends`, duplicate names, port count against the `line`, `NAME=value` instance params. Honest gap:
element values, references and DC topology inside a ps file are unchecked until ngspice runs. Top-level `.param`/`.func`
in a file are refused by the existing allowlist (a real vendor file may need editing, or a relaxed rule, later).

**Not done.** `psa`, `lt`, `ltpsa`; ps for `body`; live-mode test (live goes through the same `do_circ`).

**Tests.** `app/tests/test_compat_ps.py` (15, project-authored PSpice-syntax model with `LIMIT()`, `IF()`, `PARAMS:`,
closed-form oracles, models: path and MANIFEST, single marker and include for two instances, misuse rejected, `.control`
rejected) and `test_compat_marker_selects_ps_mode_for_one_deck_only` in the engine suite. The model is test-only (no
library package added), so `docs/library.md` is unchanged.

Proposed GAPS status: **G10 fixed** (mechanism, with the limits above stated), vendor models themselves are G19.

## G19: licence policy and vendor files

Policy: `docs/adding-components.md`, "Licence policy for third-party model files". MANIFEST fields (existing keys):
`license`, `url`, `retrieved`, `sha256`, `attribution`, plus `version`, `changes`; a vendor file needs a quoted grant.

**Vendor files added: none.** Only one grant was found in a vendor's own published terms, and I could not satisfy the
policy for any specific file:

- Analog Devices, "License agreement for Spice Models", https://www.analog.com/en/license/spice-models.html. The live
  page timed out from here (three tries); I read the Wayback copy
  (web.archive.org/web/2024/https://www.analog.com/en/license/spice-models.html). Clauses: "ADI hereby grants You a
  nonexclusive, nontransferable license to use this SPICE Model"; "You may include copies of Analog Devices' SPICE
  models with any software you sell or distribute. However, you may not make changes to the redistributed copies of
  Analog Devices SPICE models other than to: Include comments. Change nomenclature so that it will run on Your
  company's software. No changes may be made that affect the performance or function of the model."; "Analog Devices
  includes SPICE models in its library that have been developed by third parties. These models may not be
  redistributed." This is a real grant, but (a) the text came from an archive, not the live page; (b) it is per file: a
  model must be ADI-authored, which needs the file's own header, and I did not fetch any ADI file from ADI; (c) copies
  must ship unmodified, so a file needing a `.param` move (see G10) cannot be edited. Verdict: strongest candidate,
  not applied. To adopt: download a chosen ADI part's model from analog.com, check its header says ADI and not a third
  party, record the sha256 and live quote, ship byte for byte with `compat = "ps"` (or plain, if it is ngspice-clean).
