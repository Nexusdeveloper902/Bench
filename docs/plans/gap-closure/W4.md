# W4: package schema and digital (G9, G22, G24, G25)

Base 35e0a24 (the worktree was created on an older merge commit and was moved to 35e0a24 before any work).

## G9: `nc` pins

- New top-level package key `nc = [pin ids]` (`app/catalog.py`): validated against `[[pins]]` (`DEF-PIN` for an unknown or repeated id, `DEF-FIELD` if not a list of strings), stored as `Definition.nc`, with a new property `Definition.model_pins` (terminals without the `nc` ones).
- `electrical.check()` is handed only the model pins, so the node-field rule counts one placeholder per model port, and a template that mentions an `nc` pin is an unknown placeholder. A part whose pins are all `nc` fails the pin-count rule.
- `build_netlist` takes `nodes`/`used`/the 2-pin `V(Part)` test from `model_pins`; `Document.validate()` computes UNCONNECTED-PIN / UNCONNECTED-PART over the model pins only. Everything else (canvas, inspector, library table, wiring, `Document.pins`) still sees all pins, so an `nc` pin is drawn normally and can be wired. Wiring it does not change the deck.
- Documented in `docs/adding-components.md` (section "`nc` pins"). Tests: `app/tests/test_nc_pins.py`.
- One existing test call was adapted: `test_subckt_packages.py::test_every_shipped_part_passes_the_static_validator` passes the model pins to `validate_bodies`, as the catalog does.

## G24: power-on clock edge

Cause, found by probing (not what GAPS assumed): Bench runs `.tran ... uic`. Digital nodes start low and each `bench_din` adc_bridge only reports a high clock about 1 ns later, so the flip-flop sees a 0 to 1 edge with D already valid. The raw ngspice probe without `uic` does not show it.

Rejected by reasoning (not probed): the GAPS idea of a one-shot that holds clock-enable low for the first cycle. A level AND with `ready` rises with the clock when the clock is held high, so it only moves the spurious edge. Probed and rejected: a digital inverter plus latch to detect "clock seen low" (the inverter output is high at t = 0, so it arms immediately and gates nothing).

Construct used (`bench_dclk` in `io.lib`, one per clock input): two `bench_din` stages read the pin, one at the active level (P) and one at the idle level (N). Both start low and only go high when the analog pin is really at that level, so neither has a power-up event. A `d_dlatch` (data = constant 1 from a `d_pullup`, enable = N) holds `arm`; the clock to the model is `P AND arm`. A clock held at its active level never arms and never clocks; the first edge after one idle period is ordinary. Cost: about 2 bridges, a latch and an AND per clock; one ~5 ns window after t = 0 in which an edge is ignored (stated in the limitations).

Applied to every rising-edge body: `bench_d_dff`, `bench_d_jk`, `bench_d_cnt161`, `bench_d_cd4017`, `bench_d_sr595` (SRCLK and RCLK), `bench_d_sr4094` (shift clock), and the ADC clock in `conv.lib` (all widths). Not applied to the falling-edge bodies (`bench_d_jkn`, `bench_d_rip4`, `bench_d_rip12`, the QS' stage of the 4094): they already invert the clock in the digital domain, and the new tests show no power-up edge for a clock held high or low and a counted first edge. The packages' limitations are updated (the "one clock edge at power-up" sentence is gone). The combinational parts lost the sequential-only sentence. MANIFEST sha256 updated for `io.lib`, `seq.lib`, `conv.lib`.

Tests: `app/tests/test_poweron_clock.py` (11 packages: clock held high, held low, first edge from the held level, first edge from idle; includes the CD4040).

## G25: converter widths

Choice: one package per width, `ADC_4BIT`, `ADC_10BIT`, `ADC_12BIT`, `DAC_4BIT`, `DAC_10BIT`, `DAC_12BIT` (with the existing 8-bit pair). Param-driven pin groups would need a schema for pin groups, the symbol drawer, the canvas, the inspector, saved-document pin lists and versioning of a changing pin set; that is not small. The 8-bit body is a mechanical per-bit repetition, so the other widths are generated from the same pattern (a generator reproduced the shipped 8-bit text byte for byte before use) and committed as plain `conv.lib` text and `component.toml`/`symbol.svg` files. Pin ids follow the 8-bit parts (`d0`..`d(N-1)`); box height is 20 N + 60. Status: ADC `limited`, DAC `full`, as for the 8-bit pair; the limitations name the sister widths.

Tests: `app/tests/test_converter_widths.py` (DAC against `REF * code / 2^N` on sampled codes, ADC against `floor(2^N * vin / ref)`, clamp, ratiometric, clock tied high, ADC to DAC round trip).
